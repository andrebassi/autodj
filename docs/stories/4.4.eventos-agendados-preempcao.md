## Story

**As a** operador da rádio caseira,
**I want** agendar eventos fixos — Voz do Brasil, hora certa, temperatura, break comercial — com prioridade, e que eles **preemptem** a programação musical no horário certo,
**so that** a rádio toque o evento na hora exata (a hora certa às :00, a Voz do Brasil no horário legal) sem eu intervir, respeitando prioridade quando dois eventos colidem.

> **Contexto de escopo.** 4.1–4.3 montam a programação musical (clocks→grade→playlist). 4.4 adiciona a camada de **eventos agendados** que se sobrepõe: `ScheduledEvent{Kind, Schedule, Priority, MediaRef}`. O agendamento é por hora/minuto recorrente (cron-lite: dias-da-semana + hora + minuto). A **preempção** é uma função pura que, dado o instante atual + eventos + fila, decide o que injetar antes da próxima música. A execução ao vivo é 4.5 (autopilot consome esta decisão).

## Acceptance Criteria

1. **`schedule.EventKind`** enum: `voz_do_brasil`, `hora_certa`, `temperatura`, `comercial`, `programete`. `ScheduledEvent{ID, Kind EventKind, Days []time.Weekday, Hour, Minute int, Priority int, MediaRef string}` (`MediaRef` = categoria/track a tocar; vazio = gerado, ex. hora certa TTS). Tags JSON camelCase.
2. **`ScheduledEvent.Validate()`**: `ID`/`Kind` válidos, `Hour` `[0,23]`, `Minute` `[0,59]`, `Days` não-vazio e sem repetição, `Priority` `[0,100]`. Sentinelas. `ScheduledEvent.DueAt(t time.Time) bool` — true se `t` casa dia+hora+minuto (janela de 1 min). `schedule.DefaultEvents()` seed fictício. Domínio 100%.
3. **`schedule.DueEvents(events []ScheduledEvent, t time.Time) []ScheduledEvent`** — filtra os que casam `t`, **ordenados por prioridade desc** (maior primeiro). Puro. Domínio 100%.
4. **Porta `outbound.EventRepo`** (`List/Get/Save/Delete`, multi-row, método `Events()` no `TrackRepo`) + `ScheduleService.Events/SaveEvent/DeleteEvent`. Persistência memory/sqlite/postgres (migração `007`).
5. **Preempção (app).** `ScheduleService.NextInjections(ctx, at time.Time) ([]library.Track, error)`: chama `DueEvents(at)`, resolve cada evento para uma faixa (categoria via geração 4.3 ou `MediaRef` direto), devolve na ordem de prioridade — o que o autopilot (4.5) deve empurrar na frente da fila. Eventos gerados (hora certa) sem mídia → placeholder resolvido depois (TTS é Épico 6); por ora resolve para a faixa de `MediaRef` ou pula.
6. **API REST.** `GET/PUT/DELETE /api/v1/events`; `GET /api/v1/events/due?at=<rfc3339>` → eventos devidos (debug/preview). Validação → 422, body ruim → 400, not found → 404.
7. **Frontend.** `api.ts` events CRUD; hook `useEvents`; `EventsModal` (lista + editar kind/dias/hora/minuto/prioridade). Componente por arquivo. Sem listas hardcoded.
8. Gate verde: domínio 100% (Validate/DueAt/DueEvents/ordenação), `app`/`httpapi`/`memory`/`sqlite` ≥90%; `pnpm build` OK.

## Dev Notes

- **Cron-lite, não cron full:** dias+hora+minuto recorrente cobre o caso (Voz do Brasil seg-sex 19:00, hora certa toda hora :00). Sem expressão cron textual — campos estruturados, testáveis.
- **Preempção = prioridade desc.** `DueEvents` ordena; empate resolve por ordem de inserção estável. A injeção em si (mexer na `PlayQueue`) é 4.5; aqui só a *decisão*.
- **`at` injetado** via `outbound.Clock.Now()` no app — domínio recebe `t` pronto (determinístico nos testes).
- **Invariante dois-motores:** eventos resolvem para mídia local (comercial/vinheta/TTS futura). Nunca Spotify. `NextInjections` filtra mixável/PCM como 4.3.
