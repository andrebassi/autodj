## Story

As a **operador de estúdio**, I want **espalhar os painéis do player por dois
monitores e operar por toque (alvos maiores)**, so that **eu use o setup clássico
de rádio — console no monitor 1, mural "no ar" no monitor 2 — e opere numa tela
sensível ao toque sem mouse**.

## Acceptance Criteria

1. Extensão do domínio `operatorprofile` (puro, 100%), sem quebrar 7.4:
   - `Profile` ganha `Touch bool` (modo toque) e `Screens int` (contagem de
     monitores, 1 ou 2).
   - `PanelPref` ganha `Screen int` (0 = monitor principal, 1 = secundário) — só
     relevante quando `Screens==2`.
   - `Default(userID)` retorna `Touch=false`, `Screens=1`, todos os painéis em
     `Screen=0`.
2. `Validate()`:
   - `Screens==0` é tratado como `1` (compat com perfis salvos antes da 9.2);
     `Screens` fora de {1,2} → `ErrBadScreens`.
   - `PanelPref.Screen` fora de {0,1} → `ErrBadScreen`.
   - Mantém validações da 7.4 (tema, densidade, painel duplicado/desconhecido) e a
     normalização de ordem 0..n-1.
   - `normalize()` força `Screen=0` em todos os painéis quando `Screens==1`
     (defensivo: monitor único ⇒ tudo no principal).
3. Helpers puros: `AssignScreen(key, screen)` (move painel p/ monitor, ignora
   chave desconhecida), `ForScreen(n)` (painéis **visíveis** no monitor `n`, na
   ordem). `SetTouch(bool)`/`SetScreens(int)` opcionais para edição in-place.
4. Persistência: colunas `touch INTEGER NOT NULL DEFAULT 0` e
   `screens INTEGER NOT NULL DEFAULT 1` na tabela `profiles` (sqlite + postgres);
   `PanelPref.Screen` viaja no blob JSON `data` (sem coluna nova). `schema.sql`
   atualizado + migração numerada. sqlite entra no gate (round-trip de
   touch/screens/screen). postgres integration-tier (só compila). memory carrega
   por cópia de struct.
5. REST inalterado em rotas: `GET/PUT /api/v1/profile/me` já serializam o
   `Profile` inteiro — `touch`/`screens`/`screen` viajam via tags JSON. Teste
   httpapi faz round-trip PUT→GET de `touch=true`, `screens=2` e um painel em
   `screen=1`. Cobertura ≥90%.
6. UI:
   - `LayoutEditor` ganha: checkbox "Modo toque", seletor de monitores (1/2) e,
     quando `screens==2`, um seletor de monitor (1/2) por painel.
   - `useApplyProfile` carimba `data-touch` e `data-screens` no `<html>` e
     `data-screen` em cada `[data-panel]`; `globals.css` amplia alvos sob
     `[data-touch="on"]`.
   - Segundo monitor: item "🖥 Abrir 2ª tela" no menu do operador abre
     `window.open(?monitor=2)`; `page.tsx` detecta `?monitor=2` e renderiza o
     mural `SecondScreen` (no ar + fila grandes, read-only, touch-friendly) em vez
     do console. Componente único por arquivo.
   - `pnpm build` verde.

## Dev Notes

**Extensão, não reescrita.** A 9.2 só engrossa `operatorprofile` (7.4): dois
campos no `Profile`, um no `PanelPref`, dois helpers e uma regra de normalização.
Nenhum bounded context novo, nenhuma rota nova. O invariante dois-motores não é
tocado — layout é puro metadado de UI por operador.

**Back-compat de `Screens`.** Perfis salvos antes da 9.2 não têm `screens`
(decodifica 0). `Validate` coage `0→1` no topo, então um `Profile` legado valida
como monitor único. A coluna sqlite/postgres tem `DEFAULT 1`, cobrindo linhas
antigas. `Screen` por painel é `0` por ausência no blob — igualmente seguro.

**Monitor secundário = mural, não espelho.** Duas janelas de browser não
compartilham DOM, então a 2ª tela não "espelha" painéis — é uma view dedicada
(`SecondScreen`) que reusa `useNowPlaying`+`useClock` e mostra no-ar+fila grandes.
`ForScreen(1)` fica disponível no domínio para futura seleção de blocos extras no
mural, mas o mural essencial (no ar + fila) sempre aparece. `?monitor=2` é lido no
client (export estático do Next permite `useSearchParams`).

**Touch = CSS, não lógica.** `data-touch="on"` no `<html>` amplia alvos
(min-height/padding em botões e linhas) via `globals.css`. Sem estado de servidor
além do bool no perfil.

**Persistência.** `touch`/`screens` viram colunas (consulta/CHECK simples);
`Screen` fica no blob `data` junto de visible/order — zero migração de dados,
decode retrocompatível. Upsert grava as 5 colunas + blob; Get lê e remonta.

### Testing

- Domain: `Default` traz Touch=false/Screens=1/Screen=0; `Validate` coage
  Screens 0→1, rejeita Screens=3 (`ErrBadScreens`) e Screen=2 (`ErrBadScreen`);
  normalize zera Screen quando Screens==1; `AssignScreen` move/ignora-desconhecido;
  `ForScreen` filtra visíveis por monitor na ordem; regressão 7.4 (tema/densidade/
  dup/ordem) segue passando.
- sqlite: round-trip Save/Get preservando touch=1, screens=2 e panel.Screen=1;
  default de linha nova (touch=0/screens=1).
- httpapi: PUT touch/screens/screen → GET devolve os mesmos; validação 422 em
  screens fora de faixa.
