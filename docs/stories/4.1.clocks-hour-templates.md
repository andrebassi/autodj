## Story

**As a** operador da rádio caseira,
**I want** definir *clocks* (hour-templates) — o molde de uma hora como uma sequência ordenada de slots (músicas por categoria, vinhetas, comerciais, eventos) — e que esses clocks persistam,
**so that** eu tenha o esqueleto de programação de cada hora reutilizável na grade semanal (4.2) e como base da geração de playlist (4.3), sem remontar a hora toda vez.

> **Contexto de escopo.** Épico 4 = scheduler completo. 4.1 abre o épico com o **bounded context `domain/schedule`** e o primeiro agregado, o **`Clock`** (hour-template): nome + lista ordenada de `Slot`s. Cada slot puxa `Count` itens de uma `library.Category` (music/jingle/commercial/…), com um `Kind` que distingue o que preenche o slot (música de rotação, vinheta, break comercial, placeholder de evento). Esta story entrega só o **molde da hora** (CRUD persistido + editor); a *aplicação* do molde vem depois — a grade que mapeia clock→(dia,hora) é 4.2, e a materialização do clock numa playlist concreta com regras de rotação é 4.3. `GradeLoad` continua mock até 4.2.

## Acceptance Criteria

1. **Bounded context `domain/schedule`.** `SlotKind` enum fechado (`music`, `jingle`, `commercial`, `event`); `Slot{Kind SlotKind, Category library.Category, Count int}`; `Clock{ID, Name string, Slots []Slot}`. Tags JSON camelCase (`kind`, `category`, `count`; `id`, `name`, `slots`). `schedule.DefaultClocks()` devolve um seed de clocks fictícios (ex.: "Manhã", "Tarde", "Madrugada"). `Clock.Validate()`: `ID`/`Name` não-vazios, ≥1 slot, cada `Slot.Kind` válido, cada `Slot.Category` válida (`library.ValidCategory`), `Count` em `[1, 60]`, coerência kind×categoria (`jingle`→`CategoryJingle`, `commercial`→`CategoryCommercial`, `music`→`CategoryMusic`/`soundtrack`, `event`→qualquer). Sentinelas `ErrClockEmptyID`, `ErrClockNoName`, `ErrClockNoSlots`, `ErrBadSlotKind`, `ErrBadSlotCategory`, `ErrSlotCount`, `ErrKindCategoryMismatch`. `Clock.ItemCount()` soma os `Count`. Domínio 100%.
2. **Porta `outbound.ClockRepo`.** `List(ctx) ([]schedule.Clock, error)`, `Get(ctx, id) (schedule.Clock, error)` (`ErrClockNotFound` se ausente), `Save(ctx, schedule.Clock) error` (upsert por id), `Delete(ctx, id) error`.
3. **Persistência multi-row nos três repos.** `memory` (map por id, arranca vazio; seed é responsabilidade do wiring), `sqlite` (tabela `clocks(id TEXT PK, name TEXT, data TEXT)` — slots como blob JSON na coluna `data`), `postgres` (tabela `clocks` com `data jsonb`, migração `005`). `sqlite`/`postgres` compartilham o handle do `TrackRepo` via método `Clocks()`.
4. **Serviço de aplicação (inbound `ScheduleService`, parte 1).** `Clocks(ctx) ([]schedule.Clock, error)` delega ao repo; `SaveClock(ctx, schedule.Clock) (schedule.Clock, error)` valida no domínio (propaga erro sem gravar), persiste, relê e devolve; `DeleteClock(ctx, id) error`. No boot, o wiring semeia `DefaultClocks()` quando o repo está vazio (idempotente).
5. **API REST.** `GET /api/v1/clocks` → `[]Clock`; `PUT /api/v1/clocks/{id}` recebe `Clock` JSON (id do path prevalece), valida/persiste, devolve o clock atual; `DELETE /api/v1/clocks/{id}` → 204. Validação falha → 422. Body inválido → 400. Not found no DELETE/GET-by-id → 404.
6. **Frontend liga na API.** `web/app/lib/api.ts` ganha `fetchClocks`/`saveClock`/`deleteClock`; hook `useClocks` carrega/salva/remove; componente `ClocksModal` (1 arquivo, `export function`) lista clocks e edita slots (adicionar/remover slot, escolher categoria, ajustar count). Sem listas hardcoded (categorias vêm de `/library/categories`); componente por arquivo; import via `@/*`.
7. `GOWORK=off go test ./... -cover` verde: domínio 100% (todos os ramos de `Validate` + `DefaultClocks` + `ItemCount`), `app`/`httpapi`/`memory`/`sqlite`/`schedule` ≥90%. Gate `./scripts/coverage-gate.sh` passa. `pnpm build` do `web/` compila.

## Dev Notes

- **`Clock` é molde, não instância.** Slots referenciam categorias, não faixas concretas. A resolução para faixas reais (com regras de separação) é 4.3; o mapeamento clock→(dia,hora) é 4.2. Manter `domain/schedule` puro (só stdlib + `autodj/domain/library` para `Category`/`ValidCategory`).
- **Coerência kind×categoria** evita clock incoerente (slot `jingle` apontando para `music`). `event` é o único kind livre (o evento concreto entra em 4.4); no 4.1 ele só reserva posição.
- **Persistência multi-row** (≠ mix_settings single-row): id é a chave; `data` guarda os slots serializados. `Clocks()` no `TrackRepo` compartilha o mesmo `*sql.DB`/pool, como `Mixing()`.
- **Invariante dois-motores:** clock é planejamento de playout local (categorias PCM). Não referencia Spotify nem toca a matriz PCM/DRM. Nenhuma alteração em `library`/`playback`.
- **Seed no wiring, não no repo:** `memory` arranca vazio; o `cmd/server` chama `DefaultClocks()` e faz `SaveClock` de cada um quando `Clocks()` volta vazio — mantém o repo burro e o default no domínio.
