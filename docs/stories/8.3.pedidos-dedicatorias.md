## Story

**As a** operador/locutor da rádio,
**I want** receber pedidos de música e dedicatórias do ouvinte e moderá-los (aprovar/rejeitar/marcar como tocado),
**so that** eu controle a fila de participação do público — do pedido cru até a execução — com histórico auditável de cada estado.

> **Contexto de escopo.** `domain/requests` (puro) — **bounded context com estado próprio** (ao contrário de 8.1/8.2, que são projeções stateless do PlayLog). Um `Request` nasce `pending` (submetido pelo ouvinte), e o operador o transiciona: `pending→approved`, `pending→rejected`, `approved→played`, `approved→rejected`. Cada transição carimba `HandledAt`. Persistência real nos três backends (memory/sqlite/postgres). Sem cadastro de ouvinte — só nome livre + o que pediu + dedicatória opcional.

## Acceptance Criteria

1. **`domain/requests` (puro, 100%).** `Status` (`pending`/`approved`/`rejected`/`played`) com `Valid()`; `Request{ID, ListenerName, SongHint, Dedication string; Status Status; CreatedAt, HandledAt time.Time}`. `NewRequest(id, listener, songHint, dedication string, createdAt time.Time)` faz trim, exige `listener` e `songHint` não-vazios e `createdAt` não-zero, começa `pending` (`HandledAt` zero). Transições imutáveis (copy-return) `Approve(at)/Reject(at)/MarkPlayed(at)` validam a transição pela matriz de transições permitidas e carimbam `HandledAt`. Transição inválida → `ErrInvalidTransition`. Sem mutação in-place.
2. **Matriz de transições (invariante).** Permitido: `pending→approved`, `pending→rejected`, `approved→played`, `approved→rejected`. Tudo mais rejeita com `ErrInvalidTransition` (ex.: `rejected→*`, `played→*`, `pending→played`). `MarkPlayed` só de `approved`.
3. **Ports.** outbound `RequestRepo{ Save/Get/List }` + `ErrRequestNotFound`. inbound `RequestService{ Submit(ctx,listener,songHint,dedication)(Request,error); List(ctx,status)([]Request,error); Approve/Reject/MarkPlayed(ctx,id)(Request,error) }`.
3. **Persistência (3 backends).** `memory/request_repo.go`, `sqlite/request_repo.go` (+ tabela `requests` no schema/migration), `postgres/request_repo.go` (+ `migrations/013_requests.sql`). Save = upsert por id; Get = id ou `ErrRequestNotFound`; List = todos ordenados por id. postgres é integration-tier mas **compila** e é injetado no wiring.
4. **App `RequestService`** — `Submit` gera id via `Clock` injetado + contador `seq` monotônico sob mutex (`req-<unixnano>-<seq>`), cria `NewRequest` com `Clock.Now()` como `CreatedAt`, persiste. `List(status)` filtra por status (`""` = todos; status inválido → `inbound.ErrBadStatus`). `Approve/Reject/MarkPlayed` = Get→transição(`Clock.Now()`)→Save; not-found propaga `ErrRequestNotFound`; transição inválida propaga `ErrInvalidTransition`.
5. **REST** (gated em `WithRequests`): `POST /api/v1/requests` `{listener_name,song_hint,dedication}` → 201 request; `GET /api/v1/requests?status=` → lista; `POST /api/v1/requests/{id}/approve|reject|played` → request atualizado. Campos vazios (listener/song) → 422 (`ErrEmptyListener`/`ErrEmptyRequest`); status inválido no filtro → 422 (`ErrBadStatus`); transição inválida → 409 (`ErrInvalidTransition`); id inexistente → 404 (`ErrRequestNotFound`). DTO snake_case no httpapi.
6. **UI**: painel "Pedidos" — filtro por status + lista com nome/pedido/dedicatória/estado + botões de moderação (aprovar/rejeitar/tocado) conforme o estado atual. Hook + componentes (1 por arquivo). Dados só da API.
7. Gate verde: `domain/requests` 100%, `app`/`httpapi` ≥90%; `pnpm build` OK.

## Dev Notes

- **Estado real, não projeção.** 8.1/8.2 derivam do PlayLog imutável; 8.3 tem entidade com ciclo de vida próprio → três repos completos (Save/Get/List). O invariante aqui é a **matriz de transições**, não os dois-motores (pedido é metadado, não áudio).
- **Sem id-generator port.** `Submit` gera id determinístico com `Clock.Now().UnixNano()` + `seq` sob mutex (mesmo padrão já adotado). Testes usam `fixedClock` → ids estáveis por ordem.
- **Transições copy-return.** Como `linein.Input.Arm()`: recebe receiver por valor, valida, devolve cópia. Zero mutação in-place — o repo persiste a cópia nova.
- **Dedicatória opcional.** Só `ListenerName` e `SongHint` são obrigatórios. `Dedication` livre (pode ser vazio).
- **Anti-copyright:** `SongHint` é texto livre do ouvinte (ex.: "aquela dos anos 90") — não referencia catálogo real.

### Testing
