## Story

**As a** DJ,
**I want** um EQ de 3 bandas (grave/médio/agudo, com kill), um fader de pitch e um botão SYNC que alinha o BPM de um deck ao do outro,
**so that** eu faça uma mixagem harmônica e beatmatched de verdade no navegador, casando as batidas antes de cruzar o crossfader.

> **Contexto de escopo.** Depende de 5.1/5.2 (deck real + cue). 5.3 fecha a cadeia do deck: insere um `Tone.EQ3` no grafo de cada deck, um fader de pitch (`playbackRate`) e o SYNC. A matemática de beatmatch (razão de tempo a partir dos BPMs) e o clamp de pitch são **puros no domínio**; o áudio (EQ, playbackRate) é browser. O BPM vem da análise do Épico 2 (nunca do Spotify).

## Acceptance Criteria

1. **`domain/djdeck` tempo/pitch (puro, 100%).** `TempoRatio(sourceBPM, targetBPM float64) (ratio float64, err error)` — razão para casar `source` ao `target` (`target/source`); BPM ≤ 0 → `ErrNoBPM`. `PitchToRate(pct float64) float64` — pitch em % → `playbackRate` (`1 + pct/100`), `pct` clamp em [-8, +8] (padrão de pitch de DJ). `RateToBPM(baseBPM, rate) float64`. `Sync(deckBPM, masterBPM) (ratio, pitchPct float64, err error)` = combina TempoRatio + converte para % exibível.
2. **EQ3 no grafo.** Cada deck insere `Tone.EQ3` (low/mid/high em dB, faixa −∞..+6, com kill = −∞) entre a source e o gain de crossfade. `useDeck` expõe `setEQ(band, db)`; kill por banda.
3. **Pitch fader.** Slider [-8%, +8%] altera `playbackRate` via `PitchToRate` (domínio decide o valor; hook aplica). Mostra o BPM efetivo (`RateToBPM`).
4. **SYNC.** Botão por deck: pega o BPM do outro deck (o "master" implícito = deck tocando), chama `djdeck.Sync`, aplica o `playbackRate` resultante e move o fader de pitch para o `pitchPct`. Sem BPM em algum lado → botão desabilitado (tooltip "faixa não analisada").
4. **UI.** `EQ3Knobs.tsx` (3 knobs/faders + kill), `PitchFader.tsx`, botão SYNC no `Deck.tsx`, display de BPM efetivo. Componente por arquivo; BPM via API (análise Épico 2); sem lista hardcoded.
5. Gate verde: domínio 100% (`TempoRatio` ok/erro, `PitchToRate` clamp ±8, `RateToBPM`, `Sync` combinando + erro sem BPM), `web` `pnpm build` OK.

## Dev Notes

- **BPM sempre da análise local (Épico 2), nunca do Spotify** (a API do Spotify perdeu audio-features em nov/2024 — risco 1). O deck só carrega `Mixable && PCMAvailable`, que já implica análise possível.
- **Domínio decide os números, hook aplica no áudio.** `PitchToRate`/`TempoRatio`/`Sync` são funções puras testáveis; o hook só passa o `rate` para `AudioBufferSourceNode.playbackRate` e os dB para `Tone.EQ3`. O domínio NÃO importa Tone.
- **Clamp de pitch ±8%** é a convenção clássica de toca-discos (Technics). Fora disso o beatmatch fica artificial; kill de EQ = −∞ dB.
- **`Tone.EQ3`** já está na stack aprovada (plano). Carregar dinâmico no client (`"use client"`), fora do SSR.
- **SYNC não usa `time.Sleep`/relógio real** — é cálculo puro sobre BPMs; o alinhamento de fase fino (nudge) fica fora desta story (beatmatch estático por BPM basta para o gate).

### Testing

- Domínio: `TempoRatio(128,130)`=130/128, BPM 0 → `ErrNoBPM`; `PitchToRate(0)`=1, `(+8)`=1.08, `(+20)`→clamp 1.08, `(-20)`→0.92; `RateToBPM(128,1.08)`=138.24; `Sync(128, 130)` → ratio 130/128 + pitchPct ≈ +1.5625, sem BPM → erro.
