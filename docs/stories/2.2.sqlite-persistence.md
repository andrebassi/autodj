## Story

**As a** usuário da rádio caseira,
**I want** que minha biblioteca (músicas, vinhetas, comerciais) seja gravada em disco automaticamente, sem subir um servidor de banco,
**so that** o acervo e as edições sobrevivam ao reinício do app — uso pessoal não deveria exigir Postgres nem daemon nenhum.

> **Contexto de escopo.** O CRUD da 2.1 roda sobre `memory` (dev) e `postgres` (remoto). No uso caseiro real, `memory` perde tudo no restart e `postgres` é peso morto (daemon, container). A `CLAUDE.md` já documenta o **default local = SQLite por usuário logado** (`modernc.org/sqlite` pure-Go, sem cgo, 1 arquivo/user), mas o adapter não existia. Esta story implementa esse adapter e o torna o **default local**, mantendo Postgres para o caminho remoto/escala e `memory` como escape hatch de teste/efêmero.

## Acceptance Criteria

1. **Adapter `adapters/driven/sqlite`** implementa `outbound.TrackRepo` inteiro (`Upsert/List/Get/Count/Delete`) sobre `modernc.org/sqlite` (pure-Go, cgo-free), com a mesma semântica dos outros repos: `Upsert` valida no domínio antes de gravar; `List` ordena por artista/título; `Get` de id inexistente devolve erro que o app mapeia p/ `ErrTrackNotFound`; `Delete` de id inexistente devolve `library.ErrTrackNotFound`.
2. **Schema embutido, sabor SQLite.** O adapter cria a tabela `tracks` na abertura (idempotente) com tipos SQLite (`TEXT/INTEGER`, sem `TIMESTAMPTZ/now()/DOUBLE PRECISION`). Os invariantes de banco da 2.1 são preservados como `CHECK`: `source_valid`, `spotify_never_mixable` (`NOT (source='spotify' AND mixable=1)`), `category_valid` (mesmo conjunto fixo do domínio). Índices artista/título, categoria, mixable.
3. **Invariante dois-motores no banco.** Booleanos `pcm_available`/`mixable` gravados como `INTEGER` 0/1; o `CHECK spotify_never_mixable` rejeita DRM mixável no nível do arquivo SQLite também (defesa em profundidade, igual Postgres).
4. **`Open(path)`** abre/cria o arquivo, liga `PRAGMA journal_mode=WAL` e `foreign_keys=ON`, roda o schema e devolve `(*TrackRepo, closeFn, error)`. `path=":memory:"` abre banco efêmero (usado em teste). Cria o diretório-pai se não existir (ex.: `~/.autodj/`).
5. **Wiring `cmd/server` — SQLite é o default local.** Precedência: `DATABASE_URL` → Postgres (remoto/escala); senão → **SQLite** no caminho de `AUTODJ_DB_PATH` (default `~/.autodj/library.db`); `AUTODJ_DB_PATH=memory` (ou vazio + flag efêmera) → `memory`. Log diz qual repo subiu. O seed demo só popula quando a contagem é zero (primeiro boot); reinícios seguintes mantêm o que o usuário gravou.
6. **Persistência real verificada.** Subir server com SQLite, upload de 1 faixa, matar o processo, subir de novo → a faixa (e edições) continuam na lista. Sem daemon, sem container.
7. `GOWORK=off go test ./... -cover` verde com o pacote `sqlite` no gate unitário (≥90%): cobre Upsert (insert+update/upsert), List (ordem), Get (ok + not-found), Delete (ok + not-found), Count, o `CHECK` de spotify-mixable, e round-trip de todos os campos (duração, bpm, flags).

## Dev Notes

- **Por que modernc.org/sqlite.** Pure-Go, sem cgo — mantém o cross-compile do desktop (Wails) limpo e o server cgo-free, alinhado com a decisão de ffprobe/análise out-of-process. Um arquivo por usuário isola acervos sem servidor. Postgres continua para multiusuário/remoto.
- **Schema separado do Postgres.** As migrations `001/002` são sabor Postgres (`TIMESTAMPTZ`, `now()`, `DOUBLE PRECISION`, `BOOLEAN`). SQLite usa `TEXT/INTEGER/REAL`, `CURRENT_TIMESTAMP`, bool como `INTEGER`. Em vez de tentar uma migration comum, o adapter SQLite embute seu próprio `schema.sql` idempotente (`CREATE TABLE IF NOT EXISTS`) — o domínio segue sendo a fonte de verdade dos invariantes; o CHECK é defesa em profundidade.
- **Booleanos.** database/sql + modernc devolvem `INTEGER` como `int64`. Grava `pcm_available/mixable` como 0/1 (`b2i`) e lê em `int`, convertendo p/ bool no `scan`, para evitar ambiguidade de scan de bool.
- **Not-found uniforme.** `Get` devolve `sql.ErrNoRows`; o app já mapeia qualquer erro de `repo.Get` p/ `library.ErrTrackNotFound` (não precisa vazar o erro do driver). `Delete` checa `RowsAffected()==0` → `library.ErrTrackNotFound`, igual ao Postgres, p/ o 404 ser uniforme entre repos.
- **Upsert.** `INSERT INTO tracks (...) VALUES (?...) ON CONFLICT(id) DO UPDATE SET ...` (SQLite suporta upsert nativo). `Upsert` chama `t.Validate()` antes (mesma guarda dos outros repos) — categoria/ fonte inválidas nem chegam ao disco.
- **Wiring/seed.** SQLite vira default local. O seed demo em `cmd/server` roda só quando `Count==0`, então o primeiro boot popula o catálogo fictício e os seguintes preservam o que o usuário gravou (upload/edições). Para dev efêmero (testes manuais que não querem sujar `~/.autodj`), `AUTODJ_DB_PATH=memory` volta ao repo em memória.
- **Tier de teste.** Diferente do Postgres (integration-tier, precisa de servidor), o SQLite é in-process pure-Go — roda em `:memory:`/`t.TempDir()` no CI sem dependência externa, então **entra no gate unitário ≥90%** como os outros adapters puros (memory/filestore).

### Testing
