## Story

**As a** usuário da rádio caseira,
**I want** que cada faixa PCM ganhe BPM, tom (Camelot) e waveform automaticamente, em segundo plano, logo após entrar na biblioteca,
**so that** eu tenha os dados de mixagem/beatmatch prontos sem travar o upload nem rodar nada à mão — e Spotify (DRM) fica de fora, porque não dá pra analisar.

> **Contexto de escopo.** Hoje toda faixa entra com `bpm=0`, `key=""`, `waveform_ref=""` — o scan/upload só extrai metadata (ffprobe: título/artista/duração). Falta a **análise de áudio**: BPM, tom em notação Camelot e picos de waveform. A arquitetura já reserva isso (`AudioAnalyzer`/`WaveformGenerator` no plano, campos no `Track`, matriz de capacidade). Esta story entrega o **pipeline assíncrono**: após o upsert de uma faixa PCM, um worker fora do hot-path roda o analisador (binários out-of-process, cgo-free) e re-grava a faixa com os dados. Precompute no ingest = CPU zero por play (o playout só lê). Invariante dois-motores preservado: **fontes não-PCM (Spotify) nunca são analisadas** — `Marker/Beatgrid/waveform/BPM` só existem para PCM.

## Acceptance Criteria

1. **Value object de análise no domínio.** `library.Analysis{BPM, MusicalKey, WaveformRef, LoudnessLUFS}` + `Track.ApplyAnalysis(a) error`: recusa fonte não-PCM (`ErrNotAnalyzable`), rejeita BPM negativo (`ErrBadBPM`), grava os campos e re-deriva as flags via `Validate()` (não relaxa `spotify ⇒ !mixable`). Domínio 100%.
2. **Porta `AudioAnalyzer`** em `ports/outbound`: `Analyze(ctx, path) (library.Analysis, error)`. Uma implementação nunca lê DRM — recebe só `path` (arquivo PCM local).
3. **Serviço de análise assíncrono** em `app`: pool de N workers consumindo uma fila de ids; `analyzeOne(ctx, id)` (unit) busca a faixa, **pula silenciosamente** faixas não-PCM (`Analyzed`/`ApplyAnalysis` gate), chama o analyzer, aplica no domínio e re-faz `Upsert`. Falha de análise não corrompe a faixa (loga e segue). `Start(ctx)`/`Enqueue(id)`/`Stop()` com shutdown limpo. Unit-tier ≥90%.
4. **Ingest enfileira, não bloqueia.** `LibraryService.Upload` e `ScanFolder`, após um upsert bem-sucedido de faixa **PCM**, chamam `Enqueue(id)` (quando um enqueuer está ligado) — o upload responde 201 imediatamente, a análise roda depois. Faixas não-PCM não são enfileiradas.
5. **Adapter `adapters/driven/audioanalyze` (out-of-process, cgo-free).** `CLI` roda binários externos se presentes — BPM via `aubio`, tom Camelot via `keyfinder-cli`, picos via `audiowaveform` (peaks JSON gravado num dir, `WaveformRef` = caminho/ref). Ausência de binário **degrada graciosamente** (campo fica vazio, sem erro fatal), igual ao stub engine. `Noop` (sempre `Analysis{}`) para quando nenhum tool existe / dev sem análise. Nix (`flake.nix` devShell) provê aubio/keyfinder-cli/audiowaveform (regra 23 — recurso local via Nix, não Docker).
6. **Wiring `cmd/server`.** Monta o analyzer (CLI se algum binário existir, senão Noop), sobe o `AnalysisService`, liga no `LibraryService`. **Backfill no boot:** enfileira as faixas PCM ainda não-analisadas (`bpm==0`) existentes, para o acervo já gravado ganhar análise sem re-upload. Shutdown drena os workers.
7. **Status na API/UI.** `trackDTO` ganha `analyzed bool` (`Track.Analyzed()`), para o frontend distinguir "analisando…" de pronto. Sem lista hardcoded nova; o campo sai do domínio.
8. `GOWORK=off go test ./... -cover` verde: domínio 100% (incl. `ApplyAnalysis`: PCM ok, não-PCM recusado, BPM negativo recusado, waveform/key vazios não sobrescrevem); `app` ≥90% (analyzeOne: PCM analisa+regrava, não-PCM pula, not-found, erro de analyzer não corrompe; Enqueue/Start/Stop drena). `audioanalyze` com skip-if-absent.

## Dev Notes

- **Por que assíncrono/precompute.** Análise de BPM/key/waveform é cara (segundos por faixa). Rodar no upload travaria a resposta; rodar no play gastaria CPU a cada tocada. Padrão do plano: precomputa no ingest, fora do hot-path, e o playout só lê os campos já gravados. Um worker pool com fila de ids desacopla ingest de análise.
- **Out-of-process, cgo-free (igual ffprobe).** Os analisadores são binários externos chamados via `exec` — mantém o server cgo-free e o cross-compile do desktop (Wails) limpo, e evita libs nativas no binário Go. Se o binário não está no PATH, o campo correspondente fica vazio (degradação graciosa), nunca derruba o ingest. Nix provê os tools no devShell.
- **Invariante dois-motores.** `ApplyAnalysis` recusa fonte não-PCM com `ErrNotAnalyzable`; o worker pula essas faixas antes mesmo de chamar o analyzer; `Enqueue` só é chamado para PCM. Spotify nunca ganha BPM/key/waveform — coerente com a matriz de capacidade e com o CHECK de banco.
- **Idempotência.** A análise re-faz `Upsert` da mesma faixa (mesmo id) — não duplica. Backfill no boot enfileira só `bpm==0` (não re-analisa o que já tem BPM). Re-analisar (ex.: trocar de analyzer) = limpar BPM ou endpoint futuro; fora do escopo desta story.
- **Resiliência.** Erro do analyzer (binário quebrou, arquivo corrompido) é logado e a faixa segue sem análise — não corrompe o registro nem para o worker. Shutdown fecha a fila e drena os jobs em voo (`Stop` espera o WaitGroup).
- **Wiring.** `AnalysisService` implementa `AnalysisEnqueuer` (interface no `app`); `LibraryService` guarda um enqueuer opcional (nil = análise desligada, comportamento atual). Sem ciclo de import — ambos em `app`. O DTO já expõe `bpm`/`key`; só falta `analyzed` para a UI mostrar progresso.

### Testing

- **Domínio (`ApplyAnalysis`)**: PCM aceita e grava BPM/key/waveform; não-PCM → `ErrNotAnalyzable`; BPM<0 → `ErrBadBPM`; key/waveform vazios não sobrescrevem valores existentes; flags permanecem coerentes após aplicar. 100%.
- **App (`analyzeOne`/pool)**: faixa PCM com analyzer fake determinístico → BPM/key gravados e faixa re-listada com `Analyzed()==true`; faixa Spotify enfileirada por engano → pulada sem erro; id inexistente → sem panic; analyzer que retorna erro → faixa intacta; `Start`+`Enqueue`+`Stop` processa e drena sem corrida (sincronização por canal/WaitGroup). ≥90%.
- **Adapter (`audioanalyze`)**: `Noop` retorna `Analysis{}`. `CLI` com `exec.LookPath` skip-if-absent (como `TestExtractRealFile` do ffprobe); quando presente, gera um WAV via ffmpeg e confere que BPM>0 / peaks gerados.
