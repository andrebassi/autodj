## Story

**As a** operador,
**I want** tocar uma faixa `source=youtube` no deck ao vivo — o player IFrame do YouTube ocupa o **mesmo** slot de capa 60×60, só chaveando o motor,
**so that** eu use o catálogo YouTube no ar (rádio caseira/estúdio) sem redimensionar o deck e sem nunca deixar o áudio não-PCM cruzar pro bus local de mix/broadcast.

> **Contexto de escopo.** Depende de 6.5 (token/gating) e 6.6 (faixa importada). O IFrame Player API é a **única divergência estrutural** do padrão Spotify/local: exige um elemento DOM **visível** no deck (o Spotify SDK é device remoto sem elemento; o local é `<audio>` destacado). Três motores agora: Spotify (SDK, DRM, isolado), YouTube (IFrame, isolado), local (Web Audio/PCM). Invariante `youtube ⇒ mixable=false` mantém YouTube fora do crossfade PCM — transição só `fade_tts`/`hard_cut` via `setVolume(0..100)` do IFrame.

## Acceptance Criteria

1. **Player IFrame isolado.** Hook `useYouTubePlayer` carrega o IFrame Player API (`https://www.youtube.com/iframe_api`, loader memoizado em `lib/youtubeIframe.ts`), cria um `YT.Player` num **nó DOM persistente**; expõe `play(uri)`/`toggle`/`stop`/`seek`/`setVolume(0..100)` + estado (playing/posMs/durMs/currentUri) + `endedNonce` (bump no `onStateChange → ENDED`). Sem premium (YouTube não exige) — playout **nunca** gated em `Premium`.
2. **Playout no deck.** Hook `useYouTubePlayout(snap, post, wantPlay)`: gate `np.source === "youtube" && uri`; devolve `{isYouTube, live, playing, posMs, durMs}`; avança pra próxima via `endedNonce` (fallback por duração); `rampVol` via `setVolume` do IFrame (fade/TTS, nunca crossfade PCM).
3. **Iframe persistente (INVIOLÁVEL — a divergência).** UM `<div>` host do YT player mora **alto na árvore** de `page.tsx` e **nunca desmonta** (fica oculto quando ocioso). Quando a faixa ao vivo é YouTube, esse nó é **movido imperativamente** (`appendChild`, não React Portal) pra dentro do slot de capa do deck ao vivo (`<div data-yt-slot>` no `.cover-deck`, **mesmo box 60×60**). `appendChild` **move** o nó existente (iframe preservado, sem reload); Portal com alvo mutável **destruiria/recriaria** → recarregaria o vídeo (rejeitado). Ping-pong A/B do deck não recarrega o player.
4. **Seletor de motor (três vias).** `page.tsx` monta os TRÊS hooks sempre; prioridade Spotify > YouTube > local (catch-all): `playDeck = spotDeck.isSpotify ? spotDeck : youtDeck.isYouTube ? youtDeck : localDeck` (idem `playToggle`/`playSeek`/`playFadeOut`). Catch-all local apertado: `isLocal = np.source !== "spotify" && np.source !== "youtube"` — senão o motor local disputa a faixa YouTube.
5. **Isolamento três-motores (INVIOLÁVEL).** O player IFrame não compartilha `AudioContext` com deck/cartwall; nenhum nó Web Audio ligado a ele (embed, sem PCM). Nada envia áudio YouTube pro playout local nem pro Icecast. `DjDeck`/`useDeck.load` já recusam `!mixable` → YouTube fora do mix. `GET /library/tracks/{id}/audio` → 403 (não-PCM).
6. **Enqueue/drag + build.** `enqueueYouTubeSafe` (espelha `enqueueSpotifySafe`): `importYouTubeURI` → enqueue; fiado por `PlayerScreen`/`RightPanel` como `onEnqueueYouTube`; `onDeckDrop`/`ProgramList` leem `text/autodj-youtube-uri`. `task web:build` OK (IFrame client-only, sem quebrar SSR/export estático).

## Dev Notes

- **IFrame exige elemento visível (ToS + técnico).** Diferente do Spotify SDK (device remoto, sem elemento) e do local (`<audio>` destacado), o `YT.Player` monta num `<div>` que precisa estar no DOM e visível. 60×60 no slot de capa satisfaz o ToS (player não oculto/0px) — áudio é o que importa pra rádio. Documentar.
- **`appendChild` (mover), NÃO Portal (recriar).** Um Portal cujo alvo muda entre decks A/B destrói o iframe e recria → recarrega o vídeo (perde seek/estado). Mover o **mesmo** nó via `appendChild` preserva o iframe. Por isso o host é um `<div>` real nunca-desmontado alto na árvore, movido imperativamente pro `data-yt-slot` do deck ao vivo; quando ocioso volta pro host oculto.
- **Sem premium.** YouTube não expõe membership limpo e o playback não depende dela. `Premium` fica só p/ paridade do chip (best-effort, provavelmente sempre false); playout nunca gated nele. Não relaxar o isolamento por causa disso.
- **Transição fade/TTS, nunca PCM.** YouTube não dá PCM (embed) → sem crossfade/beatmatch. `rampVol` usa `setVolume(0..100)` do IFrame; auto-DJ faz volume↓ → voz → próxima↑. Mesma regra do Spotify.
- **Avanço.** `onStateChange → ENDED(0)` bumpa `endedNonce`; playout observa e chama a próxima. Fallback por duração (posMs≈durMs) cobre casos em que o ENDED não dispara.
- **`onError` do IFrame** (embeddable=false/bloqueio regional) → avançar + toast; documentar limitação.
