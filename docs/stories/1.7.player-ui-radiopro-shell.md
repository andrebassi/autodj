## Story

**As a** operador de rádio caseira,
**I want** o Player web com o layout completo do RadioPro Prime (header com relógio/RDS, decks A/B, grade rica, barra de transporte e tela Operacional com biblioteca),
**so that** eu opere a rádio com a mesma ergonomia visual do produto de referência, em uso pessoal/caseiro.

> **Contexto de escopo.** Esta story documenta, retroativamente, o *engrossamento* da UI feito durante o Épico 1 — a story `1.6` entregou o player mínimo (now-playing + fila + 2 botões); aqui o shell virou clone visual do RadioPro. Blocos de UI de Épicos posteriores (biblioteca rica = Épico 2, markers/mix = Épico 3, transporte completo = Épico 4, cartwall/deck = Épico 5, Spotify = Épico 6) aparecem como **casca navegável servida por API**, com a lógica pesada ainda diferida aos seus épicos.

## Acceptance Criteria

1. A UI tem duas abas de topo — **Operacional** (Player) e **Internet** — orquestradas por `page.tsx`, que apenas compõe componentes (nenhum JSX grande solto).
2. Toda peça de UI é um componente próprio em `web/app/components/*.tsx` (um por arquivo, `export function`); dados/mocks em `web/app/lib/`, hooks em `web/app/hooks/`; import via alias `@/*`.
3. Nenhuma lista de conteúdo é hardcoded no frontend: catálogo vem de `GET /api/v1/library/tracks`; textos/estruturas de tela vêm de `GET /api/v1/ui/{operational,webtabs,program,grade-load}`. Ícone-por-label e forma de waveform são placeholders de apresentação (permitidos).
4. O header mostra a faixa tocando (título grande), a **próxima com destaque** (chip "▸ PRÓXIMA" + nome), relógio/data, timers/RDS e a barra de carga por hora (00–23).
5. Os decks A/B refletem a convenção de fila: Deck A = `queue[0]` (= `now_playing`), Deck B = `queue[1]`; a grade lista `queue.slice(2)` — sem duplicar o que já está nos decks.
6. A barra de transporte tem 8 botões (paridade RadioPro). Só os que têm endpoint no Épico 1 ficam ativos (**FALAR**, **PLAY**, **PRÓXIMA**); os outros 5 ficam visíveis, desabilitados, com tooltip "Breve — Épico 4".
7. A tela Operacional tem categorias, busca, sub-abas (segmented control) e lista de mídias com scroller único (thead sticky) que rola o catálogo inteiro; a lista liga à fila real via `POST /api/v1/playback/enqueue` (menu de contexto + drag).
8. `npx tsc --noEmit` limpo; cobertura de `adapters/driving/httpapi` ≥90%.

## Dev Notes

- **Regra de componentes (inviolável).** `page.tsx` só orquestra. Cada bloco visual = 1 componente `export function` em `web/app/components/`. Mocks/derivações em `web/app/lib/` (`nowNext.ts`, `uiContent.ts`, `operational.ts`, `webTabs.ts`, `mockProgram.ts`, `gradeLoad.ts`, `waveform.ts`, `format.ts`, `announce.ts`, `api.ts`, `types.ts`). Fetch/estado em `web/app/hooks/` (`useNowPlaying`, `useLibrary`, `useOperational`, `useWebTabs`, `useProgram`, `useGradeLoad`, `useClock`, `useResizablePanel`). Import por alias `@/*` (→ `web/app/*`).
- **Convenção de fila (load-bearing).** O `queue[]` do WS é posicional: `queue[0]`=tocando (Deck A, = `now_playing`), `queue[1]`=próxima (Deck B), `queue[2..]`=grade. `ProgramList` usa `queue.slice(2)` para evitar a duplicata que existia (Deck B reaparecia como 1ª linha da lista). `lib/nowNext.ts` é a fonte única de now/next para header+decks (`next = queue[1] ?? queue[0]`, com fallback fictício quando a fila é curta).
- **Transport diferido.** `Transport.tsx`: só FALAR/PLAY/PRÓXIMA têm handler (endpoints do Épico 1: toggle de anúncio, `/playback/load`, `/playback/next`). LOOP/PLAY 1/PAUSE/STOP FIM/STOP JÁ recebem classe `soon` + `disabled` + `title="Breve — Épico 4 (autopilot/transport completo)"`. CSS `.tbtn.soon:disabled` (opacity 0.4, `cursor:not-allowed`, borda tracejada) distingue "não implementado" de "busy transitório". Paridade visual com RadioPro mantida; honestidade de estado preservada.
- **Contrato de mock via API.** Frontend não carrega conteúdo hardcoded. `/library/tracks` serve o catálogo (`domain/library.DemoTracks()` — 15 faixas fictícias, ids `demo-01..15`; anti-copyright). `/ui/operational` serve categorias/sub-abas/cartwall/markers/mix/spotify; `/ui/webtabs` a aba Internet; `/ui/program` as linhas ricas da grade (acima/abaixo dos decks); `/ui/grade-load` as barras de carga por hora. `useLibrary` mapeia `trackDTO → OpMedia`; `OperacionalScreen` filtra acento-insensível por intérprete/título. `demoCopies` em `demo.go` fica em **1** (bump temporário só para stress-test de scroll).
- **Sub-abas (`OpSubTabs`).** Segmented control com pill deslizante: um `<span class="opsub2-glide">` posicionado por `transform: translateX(active*100%)` sobre botões de largura igual (`flex:1 1 0`, gapless), `transition` cúbica. Labels vêm da API (`op.musicSubtabs`); `iconFor(label)` resolve o ícone só por apresentação.
- **Lista de mídias (`OpMediaList`).** `.opmedia-scroll` é o **único** scroller do painel (`<thead>` sticky). Linhas draggable quando `m.id && onEnqueue`; menu de contexto (`OpContextMenu`) e enqueue via `POST /api/v1/playback/enqueue {track_id,pos,play_now}`. Scroll verificado com 45 itens (stress) e 15 (real): `scrollHeight > clientHeight`, percorre fim-a-fim.
- **Decks/waveform.** `DeckPair`/`Deck` renderizam A (tocando) e B (CUE) com timers e waveform; a **forma** da waveform (`lib/waveform.ts`) é placeholder — waveform real é PCM-only (Épico 3). Header "▸ PRÓXIMA": chip azul (`.np-next-tag`) + nome 17px negrito (`.np-next-name`).
