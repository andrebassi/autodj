## Story

**As a** operador,
**I want** conectar minha conta Google/YouTube ao AutoDJ por um fluxo OAuth seguro (auth-code com client secret), com o token guardado por estação e renovado sozinho,
**so that** a aba YouTube saia do stub e passe a falar com a Data API de verdade (busca/import na 6.6, tocar na 6.7) — sem nunca violar o split de motores.

> **Contexto de escopo.** Abre a trilha YouTube do Épico 6, **espelho fiel do Spotify (6.1)**. Só a **autenticação**: iniciar o fluxo, tratar o callback, guardar/renovar o token e expor status/disconnect. Busca/import (6.6) e IFrame Player no deck (6.7) vêm depois e dependem daqui. **Diferença estrutural vs Spotify: Google exige auth-code COM client secret** (não PKCE público) — o secret vive só no env/`pass`, nunca no binário/código. O domínio ganha `SourceYouTube`/`YouTubeURI` e a matriz `youtube ⇒ !mixable`; esta story **não** cria faixa nenhuma, só a sessão OAuth.

## Acceptance Criteria

1. **`domain/youtube` (puro, 100%).** `Account{AccessToken, RefreshToken, ExpiresAt, Scopes []string, ChannelTitle, Premium}` com `Connected() bool`, `Expired(now) bool`, `NeedsRefresh(now) bool` (janela de folga), `HasScope(s) bool`. `CatalogItem{URI, Title, Artist(=channel), Album(=""), ArtworkURL, DurationMs, Kind}` (`KindVideo`/`KindPlaylist`). `PendingAuth{State, Verifier, CreatedAt}` com `Expired(now)` (TTL curto). Erros: `ErrNoAccount`, `ErrStateMismatch`, `ErrAuthExpired`, `ErrCatalogUnavailable`. Zero deps de rede/crypto no domínio.
2. **Persistência.** Tabela `youtube_account` (single-row por estação, SQLite + Postgres), repo `YouTubeAccountRepo` (`Load/Save/Delete`), migração. `source_valid` relaxado p/ incluir `youtube`; novo CHECK `youtube_never_mixable`; coluna `youtube_uri TEXT NOT NULL DEFAULT ''`. **Migração SQLite**: CHECK não altera in-place → **rebuild da tabela `tracks`** idempotente no open (padrão `ensureArtworkColumn`); `youtube_uri` via ALTER idempotente; `youtube_account` via CREATE IF NOT EXISTS.
3. **Porta OAuth (com secret).** `outbound.YouTubeOAuth`: `NewState() string`, `AuthURL(state, scopes) string`, `Exchange(ctx, code) (Account, error)`, `Refresh(ctx, refreshToken) (Account, error)`. Adapter real (`adapters/driven/youtube/oauth.go`) fala com `accounts.google.com/o/oauth2/v2/auth` + `oauth2.googleapis.com/token` (auth-code com `client_secret`); `channels.list?mine=true` p/ `ChannelTitle` + best-effort Premium.
4. **App service.** `YouTubeService`: `Begin(ctx) (authURL, error)`, `Complete(ctx, state, code) (Account, error)`, `Status(ctx) (connected, premium bool, error)`, `Disconnect(ctx)`, `AccessToken(ctx) (string, error)` (renova sozinho quando `NeedsRefresh`, preserva refresh_token antigo). `PendingAuth` em memória com TTL.
5. **REST.** `GET /api/v1/youtube/status` → `{connected, premium}`; `POST /api/v1/youtube/connect` → `{authURL}`; `GET /api/v1/youtube/callback?code&state` completa e **redireciona** (`302` p/ `rt.youtubeReturn`, default `/?op=youtube`), state ruim → 400; `POST /api/v1/youtube/disconnect` → 204. Rotas só existem com a option `WithYouTube(s, returnPath)`.
6. **Wiring.** `cmd/serverkit` monta o serviço só se `AUTODJ_YOUTUBE_CLIENT_ID` **e** `AUTODJ_YOUTUBE_CLIENT_SECRET` **e** `AUTODJ_YOUTUBE_API_KEY` presentes; senão desligado e rotas 404 (degradação graciosa, igual Spotify). `AUTODJ_YOUTUBE_REDIRECT` default loopback; `AUTODJ_YOUTUBE_RETURN` default `/?op=youtube`. Repo YouTube segue precedência Postgres/SQLite/memory via `.YouTubeAccount()`. State-smuggling `<sid>~<state>` reusa `sessionFromState` (provider-agnóstico) — `tenants.go` não muda.
7. **UI.** Painel YouTube gated: sem conta → tela "Conectar ao YouTube" (`YouTubeSetup`); botão **Conectar** chama `POST /connect` e navega pro `authURL`; retorno em `?op=youtube` reflete conectado; **Desconectar** limpa. Hook `useYouTube` (status/connect/disconnect). Sem busca ainda (6.6).
8. Gate verde: domínio 100%, `app`/`httpapi`/`sqlite`/`youtube` ≥90%, `task web:build` OK.

## Dev Notes

- **Auth-code COM secret (não PKCE).** Google exige `client_secret` no token exchange. Fica só no env (`AUTODJ_YOUTUBE_CLIENT_SECRET`, via gerenciador de senhas (`scripts/secrets.example.sh`)), nunca no domínio/binário público. `state` aleatório (crypto/rand) guardado no `PendingAuth`.
- **Scopes mínimos:** `https://www.googleapis.com/auth/youtube.readonly openid email profile` (readonly p/ 6.6/6.7; openid/email/profile p/ `channels.list` + best-effort premium). `access_type=offline` + `prompt=consent` p/ garantir refresh_token.
- **Token por estação, single-row** — mesma precedência/padrão de repo do Spotify (`TrackRepo.YouTubeAccount()` compartilha `*sql.DB`/pool). `Load` vazio → `ErrNoAccount`.
- **Refresh transparente:** `AccessToken()` checa `NeedsRefresh(now)` e chama `Refresh` antes de devolver; Google nem sempre devolve refresh_token novo — preservar o antigo.
- **"Premium" não mapeia:** YouTube não expõe flag limpa de membership e o playout (6.7) não depende dela. `Premium` fica best-effort (provavelmente sempre false), só p/ paridade do chip; **nunca** gateia playout. Limitação conhecida documentada.
- **Split de motores intacto:** OAuth não cria Track. Quando 6.6 importar, será `SourceYouTube` (matriz já força `!mixable`). Nada aqui toca no bus PCM.
- **Degradação graciosa:** sem as 3 vars, `WithYouTube` não é passado, rotas 404, aba YouTube some da UI.
