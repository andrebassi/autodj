## Story

**As a** operador,
**I want** conectar minha conta Spotify ao AutoDJ por um fluxo OAuth seguro (PKCE), com o token guardado por usuário e renovado sozinho,
**so that** o painel Spotify saia do stub e passe a falar com a Web API de verdade (busca/import na 6.2, tocar na 6.3) — sem nunca violar o split de dois motores.

> **Contexto de escopo.** Abre o Épico 6. Só a **autenticação**: iniciar o fluxo, tratar o callback, guardar/renovar o token e expor status/disconnect. Busca/import (6.2), Web Playback SDK (6.3) e AI DJ TTS (6.4) vêm depois e dependem daqui. **PKCE (cliente público, sem client secret)** — uso caseiro, o `client_id` é público e o secret nunca entra no binário. O domínio já modela `SourceSpotify`/`SpotifyURI` e a matriz `spotify ⇒ !mixable`; esta story **não** cria faixa nenhuma, só a sessão OAuth.

## Acceptance Criteria

1. **`domain/spotify` (puro, 100%).** `Account{AccessToken, RefreshToken, ExpiresAt, Scopes []string, Product}` com `Connected() bool`, `Premium() bool` (`Product=="premium"`), `Expired(now) bool`, `NeedsRefresh(now) bool` (janela de folga), `HasScope(s) bool`. `PendingAuth{State, Verifier, CreatedAt}` com `Expired(now)` (TTL curto). Erros: `ErrNoAccount`, `ErrStateMismatch`, `ErrAuthExpired`, `ErrNotPremium`. Zero deps de rede/crypto no domínio (verifier/challenge são gerados no adapter).
2. **Persistência.** Tabela `spotify_account` (single-row por usuário, SQLite + Postgres), repo `SpotifyAccountRepo` (`Load(ctx) (Account, error)` → `ErrNoAccount`/vazio; `Save(ctx, Account)`; `Delete(ctx)`), migração. Padrão single-row-JSON como cartwall/grid.
3. **Porta OAuth.** `outbound.SpotifyOAuth`: `AuthURL(state, challenge, scopes) string`, `Exchange(ctx, code, verifier) (Account, error)`, `Refresh(ctx, refreshToken) (Account, error)`. Adapter real (`adapters/driven/spotify`) fala com `accounts.spotify.com` (integration-tier p/ rede; `AuthURL` e o parsing de resposta testados com `httptest`).
4. **App service.** `SpotifyService`: `Begin(ctx) (authURL, error)` (gera state+verifier PKCE via porta, guarda `PendingAuth`), `Complete(ctx, state, code) (Account, error)` (valida state, troca code→token, persiste), `Status(ctx) (connected, premium bool, error)`, `Disconnect(ctx)`, `AccessToken(ctx) (string, error)` (renova sozinho quando `NeedsRefresh`). `PendingAuth` guardado em memória com TTL.
5. **REST.** `GET /api/v1/spotify/status` → `{connected, premium}`; `POST /api/v1/spotify/connect` → `{authURL}`; `GET /api/v1/spotify/callback?code&state` completa e **redireciona** pra UI (`302`), erro de state → 400; `POST /api/v1/spotify/disconnect` → 204. Rotas só existem quando o gateway está configurado (option `WithSpotify`, como `WithCartwall`).
6. **Wiring.** `cmd/server` monta o gateway só se `AUTODJ_SPOTIFY_CLIENT_ID` (+ `AUTODJ_SPOTIFY_REDIRECT`) presentes; senão o serviço fica desligado e as rotas 404 (degradação graciosa, igual Liquidsoap→stub). Repo Spotify segue a precedência Postgres/SQLite/memory.
7. **UI.** `SpotifyPanel.tsx` deixa de simular conexão: botão **Conectar** chama `POST /connect` e navega pro `authURL`; ao voltar do callback, `GET /status` reflete conectado/Premium; **Desconectar** limpa. Hook `useSpotify` (status/connect/disconnect). Sem busca ainda (6.2). Sem lista hardcoded.
8. Gate verde: domínio 100% (`Account`/`PendingAuth` lifecycle), `app`/`httpapi`/`sqlite` ≥90% (status/connect/callback ok+state-mismatch/disconnect), `pnpm build` OK.

## Dev Notes

- **PKCE, cliente público.** Sem client secret: `code_verifier` aleatório (43–128 chars), `code_challenge = base64url(sha256(verifier))`, `code_challenge_method=S256`. Gerados no adapter (crypto/rand + crypto/sha256), nunca no domínio.
- **Scopes mínimos:** `user-read-private user-read-email streaming user-read-playback-state user-modify-playback-state` (streaming/playback prep p/ 6.3; read-private p/ detectar Premium).
- **Token por usuário, single-row** — mesma precedência/padrão de repo do cartwall (`TrackRepo.SpotifyAccount()` compartilha `*sql.DB`/pool). `Load` vazio → `ErrNoAccount` (app trata como desconectado).
- **Refresh transparente:** `AccessToken()` checa `NeedsRefresh(now)` (ex.: expira em <60s) e chama `Refresh` antes de devolver; persiste o novo token. Spotify pode não devolver refresh_token novo — preservar o antigo.
- **Split dois-motores intacto:** OAuth não cria Track. Quando 6.2 importar, será `SourceSpotify` (matrix já força `!mixable`). Nada aqui toca no bus de playout.
- **Degradação graciosa:** sem `AUTODJ_SPOTIFY_CLIENT_ID`, `WithSpotify` não é passado, rotas 404, UI mostra "integração não configurada".

### Testing

- Domínio: `Account.Expired/NeedsRefresh` nas bordas do relógio; `Premium` por `Product`; `HasScope`; `PendingAuth.Expired` no TTL; `ErrStateMismatch` quando state diverge.
- `app`: `Begin` gera+guarda pending; `Complete` valida state (mismatch → erro), troca via fake gateway, persiste; `AccessToken` renova quando perto de expirar; `Status`/`Disconnect`.
- `httpapi`: `status` desconectado/conectado; `connect` devolve authURL; `callback` ok → 302, state ruim → 400; `disconnect` → 204; rotas ausentes sem `WithSpotify`.
- `adapters/driven/spotify`: `AuthURL` contém client_id/challenge/scopes; `Exchange`/`Refresh` parseiam resposta via `httptest`; erro HTTP → erro.
