## Story

**As a** operador da rádio caseira,
**I want** inserir mídias por upload no navegador (além do scan de pasta), editar metadados/categoria e apagar faixas da biblioteca,
**so that** eu faça a manutenção completa (CRUD) do acervo — músicas, vinhetas, comerciais, programetes — sem depender só de largar arquivos numa pasta.

> **Contexto de escopo.** Épico 1 entregou só `POST /library/scan` (pasta inteira) + seed demo. Não havia criar/editar/apagar faixa individual nem gestão de categoria. Esta story abre o Épico 2 com o CRUD mínimo: **upload** (multipart → salva na media dir → ffprobe → Track), **editar** (título/intérprete/álbum/categoria), **apagar** (remove registro + arquivo) e **categorias fixas validadas**. Vinheta/comercial/programete **não são tipos novos** — são um `Track` com `Category` diferente. Análise BPM/key/waveform assíncrona continua diferida (Épico 2 posterior/3).

## Acceptance Criteria

1. **Categoria é enum fixo validado no domínio.** `domain/library` define o conjunto fechado (`music, jingle, soundtrack, effect, commercial, promo, sponsorship, extra`); `Track.Validate` normaliza categoria vazia → `music` e rejeita categoria fora do conjunto (`ErrBadCategory`). Nenhuma categoria livre entra no repo.
2. **`GET /api/v1/library/categories`** serve a lista fixa com rótulo pt-BR + ícone (o frontend não hardcoda a lista de categorias; ela vem da API, como todo catálogo).
3. **Upload:** `POST /api/v1/library/upload` (multipart: `file` + `category` + opcionais `title/artist/album`) salva o arquivo via porta `MediaStore`, extrai duração/tags por ffprobe, cria `Track` local (`source=local`, `pcm_available=true`), valida e faz upsert. Responde `201` com o `trackDTO`. Categoria inválida → `422`; sem arquivo → `400`.
4. **Editar:** `PATCH /api/v1/library/tracks/{id}` atualiza só metadados editáveis (título/intérprete/álbum/categoria); nunca muda `source`/`path`/`duration`/flags. `404` se o id não existe; categoria inválida → `422`. Responde `200` com o `trackDTO`.
5. **Apagar:** `DELETE /api/v1/library/tracks/{id}` remove o registro do repo e o arquivo físico via `MediaStore` (best-effort no arquivo). `404` se não existe; `204` no sucesso.
6. **`TrackRepo` ganha `Delete(ctx, id)`** implementado em `memory` e `postgres`; migration nova adiciona `CHECK` de categoria (forward-only, mantém default `music`).
7. **UI (componentes, regra inviolável):** botão **`+ Adicionar`** na tela Operacional abre modal de upload (dropzone + seletor de categoria vindo da API); menu de contexto da lista ganha **Editar** e **Apagar**; modal de edição (`TrackFormModal`) altera metadados/categoria. Após cada mutação a lista recarrega do backend. Nada de conteúdo hardcoded.
8. **Invariante dois-motores preservado.** Upload só cria `source=local` (PCM). Nenhum caminho de CRUD marca Spotify como `mixable`. `spotify ⇒ !mixable` intacto nas 4 camadas.
9. `GOWORK=off go test ./... -cover` verde (domain 100%, adapters/app ≥90%); `npx tsc --noEmit` limpo.

## Dev Notes

- **Categoria = value object fixo (domínio manda).** `domain/library/category.go` é a fonte de verdade das chaves válidas (identificadores em inglês, regra AGENTS: só strings de UI são pt-BR). Rótulo pt-BR + ícone vivem na **camada de entrega** (`httpapi`), servidos por `GET /library/categories`; um teste em `httpapi` trava a paridade (todo domínio-key tem rótulo, nenhum rótulo órfão) p/ evitar drift. `Track.Validate` normaliza `""`→`music` (compat com scan/seed que já setam `music`) e rejeita fora do conjunto.
- **Upload path.** `MediaStore.Save(filename, reader) → path` (filestore grava em `~/.autodj/media`, sanitiza p/ evitar path traversal). O `id` continua derivado do path (sha1) p/ re-upload do mesmo nome ser upsert. ffprobe extrai duração/tags; título default = nome do arquivo se vier vazio; categoria default = form. `source=local` sempre (PCM). Sem cgo (ffprobe out-of-process, padrão do projeto).
- **Editar é metadata-only.** `UpdateTrack` faz `Get`→muta só {title,artist,album,category}→`Validate`→`Upsert`. Não toca em `source/path/duration/bpm/flags`. Isso mantém o invariante e evita que edição “promova” fonte.
- **Delete best-effort no arquivo.** `repo.Delete` primeiro (fonte de verdade); `MediaStore.Remove(path)` depois — falha no arquivo (ex.: seed demo com path fictício) não falha a request (log/ignore). Seed demo tem `path=/demo/*.mp3` inexistente; apagar seed remove só do repo.
- **CRUD na porta inbound.** `LibraryService` cresce mas continua fina (orquestra domínio+portas, sem regra). Inputs como structs no pacote `inbound` (`UploadInput`, `UpdateInput`). `Categories()` retorna `[]library.Category` (chaves); rótulo é presentation.
- **UI (regra inviolável).** `page.tsx`/`OperacionalScreen` só orquestram. Novos componentes: `UploadModal.tsx` (dropzone `POST /library/upload`), `TrackFormModal.tsx` (edição `PATCH`). `OpContextMenu` ganha Editar/Apagar (só quando `id` existe). `useLibrary` expõe `reload/uploadTrack/updateTrack/deleteTrack/categories`; `api.ts` as funções fetch. `OpMedia` ganha `category?`/`album?` opcionais p/ preencher o form de edição.
- **Migration forward-only.** `002_category_check.sql` adiciona `CONSTRAINT category_valid CHECK (category IN (...))`. Postgres é integration-tier (fora do gate unitário); o adapter `sqlite` ainda não existe (persistência local default documentada, implementação diferida) — o CRUD roda hoje sobre `memory` (dev) e `postgres` (remoto).
